# Offline review and pilot gates

The offline harness writes `review_run_hash` to `manifest.json` and stable `claim_id` values to each prediction. A human review JSONL row must contain `example_id`, that `run_hash`, the SHA-256 `prediction_hash` of the complete prediction JSON object (canonical JSON with sorted keys and `ensure_ascii=False`), the ordered `claim_ids`, and a `claims_supported` object mapping every claim ID to a boolean. It also needs nonempty `reviewer_id` and `reason`, `reviewed_at` (YYYY-MM-DD), `task_satisfied`, and `severe_unsafe`. Duplicate or stale reviews fail the run. The reviewer ID is a self-declared label, not a cryptographic signature or identity verification. An empty review file leaves quality metrics unknown. Fixture metrics do not establish hallucination reduction.

The CLI checker recognizes only `aws ec2 modify-instance-metadata-options` with a small set of literal options. Its hop limit range follows the [AWS CLI reference](https://docs.aws.amazon.com/cli/latest/reference/ec2/modify-instance-metadata-options.html). A syntax result does not prove operational correctness or safety; the checker never executes a command.

`generate_dataset.py` defaults to a write-free dry run and requires new output and raw paths. Execution additionally requires a populated pilot config, `approvals.paid_generation=true`, `--execute`, `--approve-generation`, `--allow-network`, and `--allow-paid-api`. There is no model fallback. Generated rows are `pending` until separately reviewed. The input budget is bounded conservatively by UTF-8 prompt bytes; the output token cap is passed to the API. A real pilot still needs usage and cost reconciliation against its approved budget.

`train_lora.py --validate-only` checks the pilot config, reviewed input rows, and pinned installed dependency versions without loading a model. TRL 0.15.1 uses `SFTConfig.max_seq_length`, as shown in the [tagged official source](https://github.com/huggingface/trl/blob/v0.15.1/trl/trainer/sft_config.py). Training and merging require separate config and CLI approvals. Model loading is restricted to local files with pinned revisions and remote code disabled. No training or merge run has been performed here.
